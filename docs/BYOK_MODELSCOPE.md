# 自带 API：本地验收与魔搭创空间部署

这一版在游戏顶部直接输入服务商、模型及 API Key。无需新建游戏账号，不弹出配置窗口、不打开外链。未配置时显示“离线模式”，可以完整游玩；角色使用预设对白，尚未开启 AI 自主对话。每局使用一家模型扮演全部角色，并非同时调用六家接口。

本文描述开发方案与验收步骤，不代表真实模型或魔搭线上已经验收通过。真实调用会消耗玩家自己的模型额度；连接验证也有少量消耗。

## 玩家交互

| 操作 | 预期行为 |
|---|---|
| 输入密钥，开启 AI 模式 | 先做小型连接验证，成功后启用，不重新开局 |
| 不勾选“记住” | 仅在当前服务会话中使用，不持久保存 API Key |
| 勾选“在此浏览器记住密钥” | 保存加密凭证，并通过再次请求确认浏览器是否实际接受 |
| 重新开局 | 更换对局，沿用当前模型配置 |
| 更换配置失败 | 保留原来可用的模型配置与对局 |
| 切回离线 | 当前局继续，保留可恢复的模型配置 |
| 删除密钥配置 | 删除此浏览器保存的配置，当前局继续离线游玩 |
| 密钥错误、余额不足、超时 | 区分原因并提示；不自动使用作者密钥 |

配置成功后只显示密钥末四位。原始密钥与加密凭证都不得写入 URL、应用日志、角色提示词、游戏存档或复盘。模型生成文本仍经过游戏校验；部分内容使用预设文本时会有通用提示，不能把“连接可用”解释成“每句对白都由模型生成”。

## 浏览器保存与边界

保存采用服务器认证加密后的 HttpOnly Cookie；线上使用 Secure、SameSite=None 和 Partitioned 属性，在魔搭嵌入页面中探测 Cookie 往返。加密主密钥只由应用服务器持有。玩家 API Key 会经过游戏后端解密并代调官方接口，不是“完全不离开浏览器”。

游戏会话同时支持独立的匿名会话请求头。第三方 Cookie 或存储被阻止时，仍能在当前页面连续玩；保存失败会明确提示，绝不回退到明文持久存储或要求跳出平台。浏览器隐私策略、无痕模式、网站数据清理、域名或顶层嵌入站点变更均可能使已保存配置无法访问。

凭证采用 90 天滚动期限；活跃使用以及恢复并验证成功时续期。不承诺永久保存。删除本地凭证不是向模型服务商撤销 API Key；如怀疑密钥泄漏，需在对应服务商处撤销。

“记住密钥”与“保存对局”分开：同一加密主密钥及浏览器凭证保留时，服务重启后可以恢复模型配置；当前对局仍保存在进程内，重启、部署更新或会话过期会清空。本版没有账号或跨设备云存档。

## 本地准备

在项目目录安装场景版依赖，无需为这个界面安装 Gradio：

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-scene.txt
.venv/bin/python tools/setup_cookie_secret.py
```

工具会创建 `.local/byok-cookie-secret`，文件权限为 600；再次运行复用原值，不显示或覆盖它。此文件不是玩家 API Key，不能打包、提交或公开。双击 `启动新版.command` 时，启动器会读取该文件并设置进程内的 `BYOK_COOKIE_SECRET` 后再加载游戏。直接运行 `scene_app.py` 时则需自行提供该环境变量。缺少有效主密钥或加密依赖时，仅关闭“记住密钥”，不会保存明文。

本地 HTTP 页面只能验证本地 Cookie 行为；它不能替代魔搭 HTTPS iframe 的兼容性验收。

## 魔搭部署配置

使用 **Docker 创空间**。Dockerfile 明确启动 `scene_app:app`，监听 `0.0.0.0:7860`，仅一个 worker；不要让平台默认启动根目录的 `app.py`，后者是旧 Gradio 界面。无需在容器里运行或下载大模型。

| 配置 | 放置位置 | 值与说明 |
|---|---|---|
| `BYOK_COOKIE_SECRET` | 创空间 Secret／密文配置 | 稳定的 Fernet 主密钥；不要放入公开变量、Dockerfile 或代码。更新版本时保留原值 |
| `BYOK_ENABLED_PROVIDERS` | 普通运行时变量 | 默认 `deepseek`。可识别 `deepseek,openai,anthropic`；只有满足服务地区要求、完成部署实测后才开放相应服务商 |
| `APP_PUBLIC_ORIGIN` | 普通运行时变量 | 平台实际分配给应用的 HTTPS origin，无路径、无末尾斜杠；不是外层大赛页面的 `modelscope.cn` origin |

从平台获取真实应用 origin，不猜测域名。它用于校验游戏 iframe 自己发起的请求，玩家不需要跳转到这个地址。部署端不需要也不应配置作者的 `OPENAI_API_KEY`、`DEEPSEEK_API_KEY` 等供玩家共用；场景版默认入口不读取这些作者密钥。

首次部署主密钥需在受控本地环境生成后，直接填写平台 Secret。使用本机已生成的主密钥或重新生成独立的部署主密钥均可，但后续不要每次重启重新生成。更换主密钥会使旧浏览器凭证失效，玩家需要重新录入。

Docker 只复制运行必需的 Python 源码、前端及美术素材；`.dockerignore` 使用允许列表排除历史测试记录、报告、环境文件与本机密钥。上传源码包仍应按相同允许列表组织，不能直接上传整个工作目录。

在完整本地项目中生成可部署包：

```sh
python3 tools/package_modelscope.py --list
python3 tools/package_modelscope.py
```

默认生成项目上一级目录的 `六魂新朝-v3-modelscope.zip`，包含 Docker 入口、必要源码、前端、原有素材及部署说明。ZIP 根目录直接放置 Dockerfile；解压后将这些文件作为创空间仓库根目录。工具使用固定源码允许列表和素材类型允许列表，拒绝符号链接，排除本机密钥、`.local`、环境文件、测试及历史对局。包内 `PACKAGE_CONTENTS.json` 记录实际文件大小和 SHA-256。若输出已存在，默认不覆盖；确认需要替换后使用 `--force`。

## 验收清单

本地用模拟模型响应先检查：

```sh
.venv/bin/python -m unittest tests.test_byok_api tests.test_byok_provider tests.test_credential_vault -v
node --test tests/*.cjs
```

缺少 `cryptography` 导致测试跳过，不算“加密保存已验证”。真实密钥不要加入测试夹具。部署前还需在魔搭实际页面验证：

- 桌面 Chrome、Safari 和手机布局中，输入区可见，配置、游玩、重开均不跳外链。
- 首次记住成功、刷新恢复、关闭页面后再次进入、服务重启后恢复配置；浏览器阻止存储时明确降级为本次使用。
- 两个独立浏览器的密钥、对局和统计互不混用；一个玩家等待模型不阻塞另一个玩家。
- 无效密钥、额度不足、网络超时、模型格式错误均不调用作者的额度，不泄漏密钥。
- 删除配置后再次进入不自动恢复；验证失败不重置已有进度。
- 配置的官方模型在实际服务器网络及适用服务地区下可用；仅有适配代码不代表已通过真实服务验收。

单 worker 与有限会话、并发上限适合首版测试；不要直接增加 worker 扩容，否则进程内会话无法共享。若需要多实例或重启后恢复对局，应另行设计共享会话与存档服务。
